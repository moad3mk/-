# NEXO CLOUD PRIVATE

لوحة خاصة لإدارة بوتات Discord المبنية بـ Node.js. ملفات المشروع محفوظة في GitHub، لكن GitHub ليس خادماً لتشغيل البوتات: جعل المستودع Private يحمي الكود من العرض العام فقط، ولا يشغّل الموقع أو البوتات 24/7.

## الموجود حالياً
- دخول خاص بكلمة مرور `HOST_PASSWORD` وجلسة HttpOnly.
- رفع ZIP مع حدود للحجم وعدد الملفات وفحص المسارات، ورفض الروابط الرمزية وأنواع الملفات الخاصة والمسارات غير الآمنة، مع اشتراط وجود `index.js` كملف فعلي في الجذر.
- عرض البوتات وحالتها، وتشغيلها وإيقافها وإعادة تشغيلها من اللوحة.
- عرض آخر سجلات كل بوت.
- تثبيت مكتبات البوت من `dependencies` في `package.json` مع تعطيل `install scripts`، والتحقق من أسماء المكتبات وإصداراتها، وحد أقصى 40 مكتبة ومهلة 3 دقائق، وبحد أقصى عمليتين للتثبيت في الوقت نفسه.
- حماية إضافية لطلبات لوحة التحكم: فحص `Origin` لطلبات التغيير، تحديد معدل الطلبات، وتحديد الرفع إلى 5 ملفات خلال 10 دقائق.
- تطبيق تحديد معدل الطلبات وفحص المصدر أيضاً على واجهات API القديمة، وإخفاء ترويسة تعريف Express.
- إيقاف البوت بإرسال الإشارة إلى مجموعة عملياته على Linux، ثم التصعيد إلى `SIGKILL` بعد مهلة إذا لم يتوقف.
- حماية الجلسات: كلمات مرور لا تقل عن 16 حرفاً، جلسات عشوائية HttpOnly وSameSite=Strict، حد أقصى 1000 جلسة، وتسجيل خروج يبطل الجلسة.
- رؤوس حماية المتصفح عبر Helmet وContent Security Policy، ومنع تخزين استجابات API في الذاكرة المؤقتة.
- حدود تشغيل افتراضية: 5 بوتات تعمل في الوقت نفسه و20 بوتاً مخزناً، مع إمكانية تغييرها بمتغيرات البيئة.
- صلاحيات مجلد البوتات 700 والملفات المرفوعة 600، مع حد فعلي للحجم بعد فك ZIP وليس اعتماداً على بيانات الأرشيف فقط، وإخفاء قيم متغيرات البيئة من السجلات عند تطابقها.
- تشغيل تلقائي بعد إعادة تشغيل الخادم للبوتات التي تم تشغيلها من اللوحة.
- تشغيل بوتات Linux عبر `bubblewrap` داخل مساحة أسماء منفصلة للملفات والعمليات وIPC وUTS، مع نظام ملفات أساسي للقراءة فقط ومجلد البوت وحده قابل للكتابة، وبيئة `/tmp` مؤقتة. الشبكة مشتركة حتى تعمل اتصالات Discord.
- متغيرات بيئة منفصلة لكل بوت، تحفظ في ملف `.nexo-env.json` بصلاحيات ملفات مقيدة.

## تشغيل المنصة
يلزم خادم Node.js يعمل باستمرار؛ لا يكفي فتح المستودع في GitHub. إعدادات التشغيل:
- إصدار Node.js المقترح: 22.
- مجلد المشروع: جذر المستودع.
- أمر تثبيت حزم المنصة: `npm install`.
- أمر التشغيل: `npm start`.
- متغير البيئة المطلوب: `HOST_PASSWORD`، ويجب تعيين كلمة مرور قوية وفريدة لا تقل عن 16 حرفاً من لوحة الخادم، لا داخل GitHub.
- متغيرات اختيارية: `NEXO_MAX_RUNNING_BOTS` (افتراضياً 5، أقصى قيمة 20)، `NEXO_MAX_BOTS` (افتراضياً 20، أقصى قيمة 100)، و`TRUST_PROXY=true` فقط إذا كان التطبيق خلف وكيل عكسي موثوق واحد.
- المنفذ: يستخدم المشروع قيمة `PORT` التي توفرها الاستضافة، أو 3000 عند التشغيل المحلي.
- يجب أن تكون مساحة `/app/bots` أو المجلد المحدد في `NEXO_BOTS_DIR` دائمة التخزين حتى لا تضيع ملفات البوتات عند إعادة إنشاء الخادم.

بعد تشغيل خادم Node.js، تفتح لوحة التحكم من نفس عنوانه على المسار `/cloud`. واجهة Wispbyte الثابتة الحالية ليست محرك التشغيل ولا يمكنها وحدها تشغيل هذا الخادم.

## حدود الأمان المهمة
تمت إضافة طبقة عزل أولية باستخدام `bubblewrap` على Linux: كل بوت يحصل على namespaces منفصلة للعمليات والملفات وIPC وUTS، ويرى نظام الملفات المحدد للقراءة فقط ومجلده الخاص للكتابة، مع `/tmp` مؤقت. الشبكة تبقى مشتركة للسماح باتصال Discord. إذا لم تكن الأداة موجودة أو تعذر تشغيلها، يرفض NEXO تشغيل البوت (fail-closed) بدلاً من تشغيله دون عزل.

**هذه ليست بعدُ عزلاً إنتاجياً مكتملاً لاستضافة أكواد زبائن غير موثوقة.** لم تُضف حتى الآن حصص CPU/RAM/PIDs عبر cgroups، ولا قيود خروج الشبكة، كما أن عمل `bubblewrap` داخل Docker يعتمد على دعم user namespaces وإعدادات المضيف؛ وجود الحزمة وحده لا يثبت أن العزل يعمل. يجب اختبارها على خادم Linux فعلي ومراجعة صلاحيات المضيف قبل استقبال بوتات زبائن. تعطيل `install scripts` يقلل مخاطر التثبيت لكنه لا يشغّل مدير الحزم داخل نفس sandbox.

## الاختبارات
يوجد فحص تلقائي عبر GitHub Actions عند كل تحديث على فرع `main` أو عند فتح Pull Request. نجاح هذا الفحص لا يثبت عزل عمليات البوتات ولا يختبر تشغيل بوت Discord حقيقي.
