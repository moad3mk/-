# NEXO CLOUD PRIVATE

لوحة خاصة لإدارة بوتات Discord المبنية بـ Node.js فقط. لا يشمل المشروع استضافة مواقع الويب.

## الموجود حالياً
- دخول خاص بكلمة مرور `HOST_PASSWORD` وجلسة HttpOnly.
- رفع ZIP مع حدود للحجم وعدد الملفات وفحص المسارات، ورفض الروابط الرمزية وأنواع الملفات الخاصة والمسارات غير الآمنة، مع اشتراط وجود `index.js` كملف فعلي في الجذر.
- عرض البوتات وحالتها، وتشغيلها وإيقافها وإعادة تشغيلها من اللوحة.
- عرض آخر سجلات كل بوت.
- تشغيل تلقائي بعد إعادة تشغيل الخادم للبوتات التي تم تشغيلها من اللوحة.
- متغيرات بيئة منفصلة لكل بوت، تحفظ في ملف `.nexo-env.json` بصلاحيات ملفات مقيدة.

## النشر على استضافة Node.js
المشروع جاهز للنشر من مستودع Git:
- إصدار Node.js المقترح: 22.
- مجلد المشروع: جذر المستودع.
- أمر تثبيت الحزم: `npm install`.
- أمر التشغيل: `npm start`.
- متغير البيئة المطلوب: `HOST_PASSWORD`، ويجب تعيين كلمة مرور قوية وفريدة من لوحة الاستضافة، لا داخل GitHub.
- المنفذ: يستخدم المشروع قيمة `PORT` التي توفرها الاستضافة، أو 3000 عند التشغيل المحلي.
- يجب أن تكون مساحة `/app/bots` أو المجلد المحدد في `NEXO_BOTS_DIR` دائمة التخزين حتى لا تضيع ملفات البوتات عند إعادة إنشاء الخادم.

بعد نجاح النشر، تفتح لوحة التحكم من نفس عنوان خادم Node.js على المسار `/cloud`. واجهة Wispbyte الثابتة الحالية ليست هي محرك التشغيل ولا يمكنها وحدها تشغيل هذا الخادم.

## حدود الأمان المهمة
الرابط الخاص وعدم نشره يقللان الوصول للوحة، لكنهما لا يعزلان كود البوتات. عمليات البوتات تعمل حالياً تحت حساب نظام التشغيل نفسه الذي يشغّل لوحة التحكم، وقد يتمكن كود بوت خبيث من قراءة ملفات بوتات أخرى أو ملفات الخادم التي يستطيع الحساب الوصول إليها. لذلك شغّل فقط بوتات موثوقة. لا ترفع بوتات زبائن غير موثوقة قبل إضافة عزل مستقل لكل بوت وحدود CPU/RAM/الشبكة وتثبيت اعتمادياته داخل بيئته المعزولة. تثبيت `package.json` للبوتات المرفوعة ما زال معطلاً حالياً.

## الاختبارات
يوجد فحص تلقائي عبر GitHub Actions عند كل تحديث على فرع `main` أو عند فتح Pull Request. نجاح هذا الفحص لا يثبت عزل عمليات البوتات ولا يختبر تشغيل بوت Discord حقيقي.
